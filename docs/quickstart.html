MurOS - first deployment

There are two ways to install MurOS, and both give the exact same system:

  • Option A (recommended): the installer ISO. It boots and installs itself offline, no Linux to assemble and no command line.
  • Option B: on an existing Debian 13. Install the package on top of a server you already provisioned.

MurOS targets Debian 13 (Trixie), amd64. Other distributions (Ubuntu, Rocky, RHEL) are not supported: MurOS relies on Debian-specific drop-in paths. Whatever the install path, later upgrades flow through apt.

Hardware

An x86_64 machine (VM or bare metal) with at least 1 vCPU, 2 GB RAM, 8 GB disk and two network interfaces (one WAN, one LAN). 2 vCPU and 4 GB are comfortable. See the Hardware page for sizing by throughput.

Option A: the installer ISO (recommended)

  1. Download the ISO from the Install page (or https://download.muros.org/iso/) and write it to a USB key (dd, Rufus, balenaEtcher), or attach it to a VM.
  2. Boot the machine and pick Install MurOS. Choose your keyboard layout, then the LAN interface and its static IP. The rest of the install runs automatically and offline.
  3. After reboot, open https://<the-LAN-IP>/ in any browser and accept the self-signed certificate. Log in with root / root (a value that types the same on AZERTY and QWERTY, so the first login is never blocked by a keyboard mismatch). You are asked to set a new password right away.

The LAN address you set during install is what MurOS uses. A firewall LAN is static, never DHCP: it is configured once at install and not changed from the UI. Your LAN interface is therefore already done; jump to Configure the firewall and start with the WAN.

Option B: on an existing Debian 13 (advanced)

Prerequisites:

  • A clean Debian 13 (Trixie) install, server profile (no desktop).
  • Root access (the install script must run as root).
  • At least one network interface reachable from the management subnet.
  • Outbound HTTPS to download.muros.org for the repository and package.

Run as root on the target machine:

curl -fsSL https://download.muros.org/install.sh | sudo bash

The script prepares apt (repairs a loopback-only /etc/resolv.conf, disables any leftover CD-ROM apt source, clears a half-configured dpkg state), imports the repository signing key, writes /etc/apt/sources.list.d/muros.list, removes competing network managers (NetworkManager, ifupdown, netplan, dhcpcd, systemd-resolved) that conflict with the MurOS control plane, then installs the muros package. Per-site feature daemons stay dormant until you enable them from the UI. At the end it prints something like:

MurOS installed.

  UI     : https://192.168.1.10/  (self-signed cert, accept the browser warning)
  Login  : root  (use the existing root password; MurOS does not change it)

Open the UI and log in as root with your existing system root password. MurOS does not touch it, so there is nothing to reset on first login.

Upgrades

Every install, ISO included, upgrades the same way:

apt update && apt install --only-upgrade muros

Configure the firewall

MurOS stages every change in its database first; nothing touches the kernel until you click Apply. Network and firewall applies open a confirmation countdown (60s by default) and auto-roll-back if you lose access, so you can never lock yourself out of the box.

1. Interfaces (Network > Interfaces)

WAN: click the interface facing the Internet (e.g. eth0 or ens3), set IP mode static or dhcp depending on your uplink. If static, set the IP with its CIDR mask, gateway and DNS. Save.

LAN (Option B only - the ISO already set it): click the internal interface, IP mode static, e.g. 10.0.0.1/24. Save.

An orange banner shows the unapplied network changes. Click Apply, check you still have UI access, then Confirm.

2. Zones (Firewall > Zones)

Add a wan zone (the WAN interface) and a lan zone (the LAN interface). Filter rules reference zones, not interfaces, so adding a second LAN card later keeps the rules working.

3. Filter rules (Firewall > Filter rules)

The default ruleset drops everything in input and forward, so you only add what you want to open:

  • forward lan -> wan, action accept (LAN reaches the Internet)
  • input lan -> firewall, tcp ports 22 and 443, accept (SSH + UI from the LAN)
  • input lan, protocol icmp, accept (ping the firewall from the LAN)

The WAN zone keeps no rule toward the firewall, so the box stays closed from the Internet. Click Apply, then Confirm.

4. NAT (Firewall > NAT)

Add a rule: type masquerade, egress interface = your WAN interface, source = your LAN network (e.g. 10.0.0.0/24). Save and Apply. The LAN can now reach the Internet through the firewall.

Test from a LAN host

Plug a PC into the LAN, static IP 10.0.0.50/24, gateway 10.0.0.1, DNS 1.1.1.1. From the PC:

ping 10.0.0.1            # firewall reachable
ping 1.1.1.1             # Internet OK
curl -k https://10.0.0.1/  # UI reachable from LAN

If everything responds, your firewall is running.

Next steps (optional)

  • LAN services: hand out addresses and resolve names for the LAN from Services > DHCP server and Services > DNS server (the recursive resolver is on by default). See the Services page for the full list.
  • WireGuard VPN: VPN > WireGuard, generate a server key, add a peer.
  • TLS certificate: Administration > HTTP access, upload one or regenerate the self-signed cert with your own CN.
  • High availability: Administration > High availability, pair a second firewall active/passive.
  • Observability: Observability > Remote syslog, SNMP and Notifications.

Locked out?

The console always keeps root access. If a too-strict rule or a failed rollback locks the UI, one command resets the firewall:

nft flush ruleset
systemctl restart muros-backend

The UI is reachable again. See the FAQ for the other classic traps.
