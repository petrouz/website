MurOS services

Besides filtering, NAT and VPN, MurOS runs the infrastructure services a firewall is usually expected to provide. Each one has its own page in the UI and is only written to the system when you click Apply.

DHCP server (IPv4)

Hands out IPv4 addresses to LAN hosts using ISC Kea. Per interface you define a pool (range), the lease time, and the options pushed to clients (gateway, DNS, domain). Static leases bind a fixed address to a MAC so a host always gets the same IP.

Managed in Services > DHCP server.

DHCPv6 server

Stateful IPv6 address assignment, also through Kea. You hand out addresses from a per-interface IPv6 pool, the IPv6 equivalent of the DHCP server above.

Managed in Services > DHCPv6 server.

DNS server

A recursive DNS resolver for the LAN, backed by Unbound. It resolves names for your internal clients and can serve local records (name to IP) for hosts on your network. It is enabled by default.

This is the resolver MurOS offers to the LAN. It is not the same thing as the appliance's own resolver (the one apt, curl or ntp use on the firewall itself), which is managed separately. By default the firewall keeps its own upstream resolver; an opt-in option can point the appliance at its local Unbound instead.

Managed in Services > DNS server.

NTP server

Time synchronization through chrony. The firewall keeps its own clock in sync with upstream time sources and can serve time to the LAN. A correct clock matters for logs, certificates and VPN.

Managed in Services > NTP server.

Dynamic DNS

Keeps one or more hostnames pointed at the firewall's current public IP. Useful when the WAN address is dynamic and you need a stable name to reach a VPN endpoint or a published service from the outside.

Managed in Network > Dynamic DNS.

QoS / traffic shaping

Egress bandwidth prioritisation per interface, using the kernel's HTB with fq_codel. You cap the total egress rate of an interface, split it into classes with guaranteed and ceiling rates, and assign traffic to a class with match rules (by protocol, port or address). This keeps interactive traffic responsive when the link is saturated.

Managed in Network > QoS / Shaping.

Remote syslog

Forwards the firewall's journald / syslog messages to a central syslog server or SIEM, over UDP or TCP, through rsyslog. Use it to keep logs off the box and to centralise them with the rest of your fleet.

Managed in Observability > Remote syslog.

SNMP

Exposes read-only metrics for monitoring tools. Both SNMP v2c (community string) and v3 (USM, with authentication and privacy) are supported.

Managed in Observability > SNMP.

Email notifications

Sends email alerts on critical events. Configure the SMTP relay and the recipients so the firewall can warn you when something needs attention.

Managed in Observability > Notifications.
